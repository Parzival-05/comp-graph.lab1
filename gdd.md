# Дизайн-документ проекта

## 1. Цель проекта

Создать десктопное приложение для моделирования и визуализации поведения котов на прямоугольной карте. Приложение должно демонстрировать взаимодействие котов в реальном времени до 50000 котов.

Проект предназначен для учебных целей, демонстрации навыков разработки симуляций и моделирования поведения агентов. Также может быть интересен для энтузиастов компьютерного моделирования и визуализации.

## 2. Технические требования

### 2.1 Выбор технологий
- **Язык программирования:** Kotlin
- **Фреймворки и библиотеки:**
    - [Jetpack Compose](https://developer.android.com/compose) (для UI и визуализации). Был выбран как самый
      развитый из всех фреймворков и как наиболее знакомый (у одного из авторов был с TornadoFX, ему не очень
      понравилось)
    - [TinSpin Indexes](https://github.com/tzaeschke/tinspin-indexes) (реализация kd-дерева на JVM для эффективного
      поиска соседей). Был выбран как самый быстрый из всех реализаций kd-дерева.
- **Архитектура:** Использование корутин для параллельной обработки моделирования и отрисовки.

### 2.2 Платформа
Десктопное приложение, совместимое с операционными системами Windows, macOS и Linux.

## 3. Архитектура системы
### 3.1 Компоненты системы

- **Основной модуль (`main.kt`):**
    - Инициализирует и запускает приложение.
    - Загружает конфигурацию из файла `config.properties`.
    - Создает экземпляры генератора котов (`CatGenerator`) и сцену симуляции (`CatScene`).
    - Управляет состоянием UI с помощью состояния `UIStates`.
    - Использует корутины для выполнения моделирования и обновления UI.

- **Модуль состояний UI (`UIStates`):**
    - **`UIStates`**: Перечисление, представляющее различные состояния пользовательского интерфейса во время симуляции:
        - `MODELING`: Состояние моделирования и вычисления.
        - `UPDATE_DATA`: Состояния обновления данных сцены.
        - `DRAWING`: Состояние отрисовки обновленных данных на UI.

- **Модуль отрисовки (`drawing`):**
    - **`CatSimulationScreen`**: Основной компонент для отрисовки сцены и статистики.
        - **`updateScene`**: Компонент для обновления сцены, проверяя текущее состояние UI и передавая обновленные данные котов в UI.
        - **`drawScene`**: Отвечает за визуализацию котов на карте.
        - **`drawStatistics`**: Отображает статистику моделирования, такую как время моделирования и количество котов в различных состояниях.

    - **`catUtils`**: Утилиты для работы с котами.
        - **`getColorForState` и `getColor`**: Функции для определения цвета котов на основе их состояний и ролей.
        - **`wrapPosition`**: Функция для обработки позиций котов, позволяющая им покидать карту.

    - **Подмодули меню (`drawing.menu`):**
        - **`logging` (`drawInteractionLog`)**: Отображает последние взаимодействия между котами, ограничивая их количество до `MAX_LOGS_DISPLAYED`. Использует `LazyColumn` для эффективного отображения списка логов.
        - **`menu` (`drawDraggableMenu`)**: Создаёт перетаскиваемое меню с кнопками для управления видимостью логов, открытия настроек и паузы/возобновления симуляции. Включает компоненты для отображения логов и меню настроек.
        - **`sceneConfig` (`sceneSettingsMenu`)**: Меню настроек сцены, позволяющее пользователю изменять параметры симуляции, такие как количество котов, размер котов, периодичность обновлений (`tau`) и скорость котов. Включает проверку на допустимость вводимых значений и отображение ошибок через диалоговые окна (`AlertDialog`).

- **Генераторы (`radar.generators`):**
    - **`CatGenerator`**: Генератор для создания новых экземпляров котов (`CatParticle`) с начальными координатами, случайно распределёнными по сетке симуляции.
    - Реализованы несколько генераторов смещений для разнообразных паттернов движения котов:
        - Все генераторы смещений используют **равномерное распределение** для генерации случайных параметров, таких как скорости, углы и радиусы. Кроме того, каждое смещение по осям X и Y не превышает `maxParticleSpeed`, гарантируя контроль над скоростью движения каждого кота.
        1. **Линейные смещения (`LinearOffsetGenerator`)**: Генерируют постоянное движение в заданном направлении по осям X и Y.
        2. **Круговые смещения (`CircularOffsetGenerator`)**: Обеспечивает движение по круговой траектории. При каждом вызове метода `generate` выполняются следующие шаги:
            1. **Подсчет угла:**
                - Угол `angle` увеличивается на значение угловой скорости `angularVelocity`, которое рассчитывается как отношение максимальной скорости кота `maxParticleSpeed` к 100. Это обеспечивает плавное и устойчивое круговое движение:
                  $\text{angle} = (\text{angle} + \text{angularVelocity}) \mod 2\pi$
            2. **Вычисление смещения:**
                - Используется угол `angle` и заданный радиус `radius` для расчёта смещений по осям X и Y с помощью функций косинуса и синуса:

                  $\text{offsetX} = \text{radius} \times \cos(\text{angle})$

                  $\text{offsetY} = \text{radius} \times \sin(\text{angle})$

        3. **Криволинейные смещения (`CurvedLinearOffsetGenerator`)**: Обеспечивает плавные криволинейные траектории движения котов, добавляя синусоидальные колебания к линейной скорости. Для этого рассчитываются смещения по осям X и Y с использованием функций `sin` и `cos`, зависящих от "времени" в симуляции и заданных параметров кривизны (`curveFactor`) и частоты (`frequency`).
        4. **Случайные смещения (`MoveGenerator`)**: Генерируют случайные равномерно распредленные смещения.
        5. **Стремящиеся к цели смещения (`SeekTargetOffsetGenerator`)**: Кот определяет направление от своей текущей позиции к целевой точке и нормализует этот вектор, чтобы смещение не превышало `maxParticleSpeed`.

        - **Фабрика генераторов (`MovementGeneratorFactory`)**: Случайным образом выбирает один из доступных типов генераторов с равномерным распределением вероятностей, обеспечивая разнообразие поведения котов.

    - **Влияние распределения на поведение:**
        - Использование равномерного распределения гарантирует, что все возможные направления и скорости движения котов представлены одинаково вероятно, что способствует более естественному и непредсказуемому поведению агентов в симуляции.

- **Модуль сцены симуляции (`CatScene`):**
    - Управляет состоянием мира, включая владение котами (`particles`) и обеспечение их взаимодействия.
    - По умолчанию использует механизм обнаружения коллизий (`KDTreeCollisionDetection`) для эффективного поиска соседних котов, но алгоритм заменяем (для тестирования).
    - Обновляет состояние сцены в каждом цикле моделирования, обрабатывая перемещения котов и их взаимодействия.

- **Модуль обработки взаимодействий (`collisionDetection`):**
    - **`KDTreeCollisionDetection`**: Реализация обнаружения коллизий с использованием kd-дерева для быстрого поиска соседей.
    - Обрабатывает обнаруженные коллизии, обновляя состояния вовлечённых котов и записывая их в лог.

- **Модуль логирования (`radar.logging`):**
    - **`InteractionLogger`**: Управляет записью и хранением логов взаимодействий между котами.
    - Логи отображаются в UI через компонент `drawInteractionLog` и ограничиваются по количеству для поддержания производительности.

## 4. Моделирование поведения котов

Для управления поведением котов использованы деревья поведения (англ. behavior tree).
Деревья поведения позволяют комбинировать условия и действия, создавая сложные и гибкие паттерны поведения для разных ролей котов.
В нашем проекте на них завязана вся логика: от передвижения до взаимодействия с другими котами.

В ходе разработки было принято решение сделать свою реализация деревьев поведения, так как существующие решения не
удовлетворяли ряду условий: совместимость с лицензией и определенная функциональность вершин деревья.

### 4.1 Паттерны поведения

Коты в симуляции могут иметь различные паттерны поведения, определяемые их ролью:

- **DEFAULT**: Стандартное поведение включает прогулку, шипение, драку и сон.
- **GHOST**: Поведение призрак-кота включает движение к другим котам и попытки их "одержать".
- **POSSESSED**: Поведение одержимых котов включает случайные движения и отсутствие взаимодействий.

### 4.2 Менеджеры поведения
Класс `BehaviorManagerFactory` создаёт соответствующий `CatBehaviorManager` на основе роли кота:

- **DEFAULT**:
    - Перемещение случайным образом.
    - Проверка на наличие ближайших котов для шипения или драки.
        - **Шипят:** Если кот находится на расстоянии \(R_0 > r_0\) от другого кота.
        - **Драка:** Если кот находится на расстоянии \(r_0\) или меньше от другого кота.
    Каждый кот, участвующий в драке, получает урон. Если очки здоровья кота достигают 0, он переходит в состояние смерти
    - Переход в состояние сна с определённой вероятностью.
    - Смерть кота и переход в призрачную роль.

- **GHOST**:
    - Поиск ближайших котов для "одержания".
    - Перемещение к целевому коту.
    - Одерживание кота при достижении нужного расстояния.

- **POSSESSED**:
    - Случайные движения без конкретной цели.

### 4.3 Алгоритмы движения
Коты перемещаются в случайные точки в окрестности своего текущего положения за каждую периодичность \(\tau\). При движении используются различные функции расстояния:
- **Евклидово расстояние**
- **Манхэттенское расстояние**
- **Криволинейное расстояние**

### 4.4 Переходы между состояниями
Переходы между состояниями происходят на основе расстояния до ближайших котов и вероятностей взаимодействий, как описано в условии задачи.

### 4.5 Обработка взаимодействий
Используется kd-дерево из библиотеки TinSpin Indexes для эффективного поиска соседних котов и определения их взаимодействий.

### 4.6 Обновление данных
Данные обновляются с периодичностью `tau` секунд. В рамках каждой итерации дерево поведения "тикается" и
происходят следующие обновления:
- Обновляются позиции котов.
- Обрабатываются взаимодействия между котами.
- Состояния котов изменяются в соответствии с алгоритмами поведения.

- **Система перемещений:** Коты движутся в направлении с возможностью случайного отклонения угла при каждом шаге.
- **Логирование:** Все взаимодействия записываются с указанием вовлечённых котов, типов взаимодействий и временных меток.

- **Покидание карты:** Коты, покидающие границы карты, автоматически спаунятся на противоположной стороне или случайной границе.

## 6. Пользовательский интерфейс

### 6.1 Дизайн интерфейса
- **Основное окно:** Отображает карту с котами в реальном времени.
- **Панель управления:** Позволяет изменять параметры симуляции, такие как `tau`, количество котов и другие настройки.
- **Статистика:** Отображает текущие показатели, такие как количество котов в разных состояниях, количество взаимодействий и т.д.
- **Лог:** Возможность просмотра логов взаимодействий котов.

### 6.2 Взаимодействие с пользователем
- Пользователь может:
    - Запускать и останавливать симуляцию.
    - Изменять параметры симуляции в реальном времени. Например:
        - Менять число котов на карте.
        - Менять движения скорость котов.
        - Выбирать различные функции расстояния для анализа взаимодействий.
    - Просматривать лог-файлы взаимодействий.

## 7. Тестирование и обеспечение качества

### 7.1 Стратегия тестирования
Для обеспечения высокого качества и надёжности приложения реализована комплексная стратегия тестирования, включающая следующие виды тестирования:

- **Модульное тестирование (Unit Testing):** Тестирование отдельных модулей и компонент системы:
    - Узлы деревьев поведения (`Behavior Tree Nodes`)
    - Генераторы смещений (`Movement Generators`)
    - Системы обнаружения коллизий (`Collision Detection Systems`)

- **Интеграционное тестирование (Integration Testing):** Проверяется взаимодействие между различными модулями, например, между системой обнаружения коллизий и логированием взаимодействий или между генераторами смещений и менеджерами поведения котов. Это гарантирует корректное совместное функционирование отдельных компонентов.

- **Ручное тестирование (Manual Testing):** Для тестирования UI в основном проводится ручная проверка: проверка корректности отображения котов, статистики, изменения настроек симуляции, визуальное качество.

- **Тестирование дерева поведения (Behavior Tree Testing):** Специфические тесты для проверки корректности выполнения узлов деревьев поведения (`Behavior Trees`) для разных ролей котов (`DEFAULT`, `GHOST`, `POSSESSED`). Это включает проверку переходов между состояниями, выполнения условий и действий в различных сценариях.

- **`KDTreeCollisionDetectionTest`:** Этот набор тестов проверяет корректность работы алгоритма обнаружения коллизий, основанного на kd-деревьях (`KDTreeCollisionDetection`). Тесты сравнивают результаты данного алгоритма с брутфорс методом (`BruteForceCollisionDetection`) для обеспечения точности. Включены как заранее определённые сценарии с известным числом коллизий, так и случайные тестовые случаи для проверки устойчивости алгоритма при различных конфигурациях.

### 7.2 Автоматизированное тестирование

Автоматизированное тестирование реализовано с использованием следующих инструментов и фреймворков:

- **JUnit 5:** Основной фреймворк для написания и выполнения тестов. Используется для создания модульных и интеграционных тестов, обеспечивая структурированное и понятное написание тестовых кейсов.

- **Mockito:** Используется для создания имитаций (`mocking`) зависимостей и объектов, что позволяет изолированно тестировать компоненты без необходимости взаимодействия с реальными зависимостями.

- **Kotlin Test:** Дополняет JUnit и Mockito, предоставляя дополнительные утилиты и функции для упрощения написания тестов на языке Kotlin.
